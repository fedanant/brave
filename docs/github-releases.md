# Публикация сборок в GitHub Releases

После успешного завершения всех выбранных сборок workflow **Build Brave with
debloat policies** автоматически публикует результат во вкладке
[Releases этого форка](https://github.com/fedanant/brave/releases).

## Запуск

1. Слейте PR с конфигурацией в основную ветку и подключите облачные runner'ы
   по [инструкции](cloud-runners.md).
2. Откройте **Actions → Build Brave with debloat policies → Run workflow**.
3. Выберите ОС, архитектуру macOS и источник. Нажмите **Run workflow**.
4. Дождитесь завершения сборок и job **Publish GitHub release**.
5. Откройте **Releases** и скачайте файлы для своей ОС/архитектуры.

Публикация входит в workflow сборки. Push и PR запускают только проверки
скриптов; сами по себе они не создают релиз и не запускают компиляцию Brave.
Облачные машины workflow не арендует. Полная инструкция сборки находится в
[brave-debloat-ci.md](brave-debloat-ci.md).

## Содержимое релиза

- Установщики и ZIP браузера с префиксом ОС/архитектуры в имени. Имена
  Windows installer и macOS packages не конфликтуют между платформами.
- ZIP политик для каждой платформы, включая инструкцию установки и отката.
- Сведения о версии Brave/Chromium, фактических коммитах и параметрах сборки.
- Общий manifest релиза и `SHA256SUMS` для проверки файлов.

Скрипт проверяет исходные контрольные суммы, комплектность выбранных платформ
и совпадение исходников перед первым обращением на запись к GitHub. Артефакты
каждой платформы скачиваются в отдельную директорию. При повторе неудачных
jobs допускаются успешные артефакты предыдущей попытки того же запуска.

Сначала создается draft, затем загружаются файлы и только после этого релиз
публикуется. Если загрузка оборвалась, остается черновик; готовый опубликованный
релиз не перезаписывается. Повтор workflow получает отдельный тег с номером
запуска и попытки. При ошибке любой выбранной сборки публикация не выполняется.

Релиз включает именно выбранные платформы, а не обязательно все четыре пары
ОС/архитектуры. Поэтому workflow не назначает ему общую метку **Latest**.
Список **Releases** показывает опубликованные сборки; состав указан в описании.

## Доступ и ограничения

Используется штатный `GITHUB_TOKEN` с `contents: write` только в job публикации.
Отдельный PAT и секрет с личным токеном не требуются. В репозитории должны быть
разрешены GitHub Actions и создание релизов этим токеном. Ограничения организации
или правила защиты тегов могут потребовать настройки администратора.

Файл Release должен быть меньше 2 GiB; слишком большой пакет отклоняется до
создания релиза. Обычные Actions artifacts сохраняются также на 7 дней,
а Release assets не имеют этого срока удаления.

Публикация в Releases предоставляет установщики для ручного обновления. Она
не добавляет кнопку установки в браузер, подпись Windows/macOS или Apple
notarization. Автообновление через официальные каналы Brave отключено,
включая отдельный механизм Sparkle на macOS.

## Проверка

```text
python -m unittest discover -s scripts/tests -v
actionlint .github/workflows/build-brave-debloat.yml .github/workflows/validate-brave-debloat.yml
```

Тесты используют временные небольшие пакеты и подменяют вызовы GitHub CLI;
настоящие релизы при проверке не создаются. Публикация реальных браузерных
пакетов проверяется после первой успешной компиляции на облачных runner'ах.

Источники: [GitHub CLI release create](https://cli.github.com/manual/gh_release_create),
[release edit](https://cli.github.com/manual/gh_release_edit),
[ограничения GitHub Releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).
